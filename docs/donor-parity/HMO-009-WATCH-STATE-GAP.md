
# HMO-009.01 — Durable Watch request state (child of HMO-009, linked from P08)

Status: **OPEN — store, request-flow helpers and the web-process runtime landed; the Watch routes are wired on `main` (PR #298, merge `53ea099`, Oracle `40629005740` and `40629004829` success). Parity is not yet claimed: no route-level test on the wired path and the Internet Archive fallback is unported.** Recorded from donor `main` `8401114` and Apollo `main` `12c4121`.

- **Donor source:** `src/lib/watch/watch-request-service.ts` keeps two in-memory Maps, `pendingRecommendations` (keyed `sessionId:userId`) and `seriesProgress` (keyed per user and series). Both are persisted as JSON to `WATCH_STATE_FILE` (default `/data/watch-state.json` when `FLY_APP_NAME` is set, else `./data/watch-state.json`) with a `.bak` copy. Load and save helpers are `loadWatchStateFromDisk` and `saveWatchStateToDisk`, around lines 181–240. Save points are around lines 531, 553, 997, 1014, 1070, 1116, 1146, 1264 and 1308.
- **Donor consumers:** an Internet Archive fallback stores a recommendation when no provider item matches (around line 996). Accepting a recommendation reads and deletes it (around line 1135). Series progress is written after a series episode plays, using the next season and episode numbers (around line 806). `worker/PROCESS_GROUP_CUTOVER.md` notes that Lounge selections also live in this file.
- **Apollo source before this work:** missing. Movie playback sessions persist in `hmo_media_sessions` (`apps/hearmeout/src/room-media-core.ts`). Nothing in Apollo stored pending recommendations or series progress. `apps/hearmeout/src/xtream-provider.ts` accepts a `getProgress` callback, but no implementation is wired in.
- **Difference:** a restart drops pending recommendations and series resume points.
- **Store (landed on `main` via #292, Oracle `40594995273` success on `7b126d0`):** `apps/hearmeout/src/watch-state.ts` (`HearMeOutWatchStateStore`) uses STRICT SQLite tables `hmo_watch_recommendations` and `hmo_watch_series_progress`, scoped by tenant and user, with take-on-accept. It rejects playback URL, credential and malformed fields. Restart coverage: `tests/hearmeout-watch-state-restart.test.mjs`.
- **Request-flow helpers (landed on `main` via #295, merge `788b767`, Oracle `40605339364` and `40605373397` success on `main`):** `apps/hearmeout/src/watch-request-flow.ts` exports `seriesProgressLookup`, `requestWatch`, `recordRecommendation`, `acceptRecommendation` and `recordSeriesEpisodeQueued`, with provider access injected through `WatchRequestDeps`. Tests: `tests/hearmeout-watch-request-flow.test.mjs`. `apps/hearmeout/src/watch-runtime.ts` (PR #297) wraps them for the web process, and `web-server-v3.ts` (PR #298) calls them from `POST /api/hearmeout/rooms/:id/watch/request` and `/watch/accept`. `recordQueued` runs after `rooms.enqueue`; a store failure after enqueue leaves the item in the room (open decision).
- **Remaining blockers for P08 parity:**
  1. Series playback: `xtream-episode-*` playback goes through the existing HLS route (`xtreamHlsUrl` maps `/activity-provider/xtream/episode/<id>-<ext>` to `/api/watch/xtream/hls/episode-<id>-<ext>/index.m3u8`). Still needs a test that an accepted episode plays through that route.
  2. Credential boundary: resolved by design. Watch request, accept and the Xtream lookups run in the web process; there is no internal route to the media worker.
  3. Store path: `HEARMEOUT_WATCH_STATE_PATH` (default `hearmeout-watch-state.sqlite` next to `HEARMEOUT_ROOM_DATABASE_PATH`) is read in `watch-runtime.ts`. Confirm with a test.
  4. Internet Archive fallback calling `recordRecommendation` is not ported. HMO-009.01 stays open until it is.
  5. Route-level tests for request, accept and the restart path through the real HTTP handler are missing.
- **Next:** add those route-level tests, then close the fallback item or make it an explicit child ID.
