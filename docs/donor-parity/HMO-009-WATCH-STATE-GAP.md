
# HMO-009.01 — Durable Watch request state (child of HMO-009, linked from P08)

Status: **OPEN — store and request-flow helpers landed and CI-verified; no runtime caller yet.** Recorded from donor `main` `8401114` and Apollo `main` `12c4121`.

- **Donor source:** `src/lib/watch/watch-request-service.ts` keeps two in-memory Maps, `pendingRecommendations` (keyed `sessionId:userId`) and `seriesProgress` (keyed per user and series). Both are persisted as JSON to `WATCH_STATE_FILE` (default `/data/watch-state.json` when `FLY_APP_NAME` is set, else `./data/watch-state.json`) with a `.bak` copy. Load and save helpers are `loadWatchStateFromDisk` and `saveWatchStateToDisk`, around lines 181–240. Save points are around lines 531, 553, 997, 1014, 1070, 1116, 1146, 1264 and 1308.
- **Donor consumers:** an Internet Archive fallback stores a recommendation when no provider item matches (around line 996). Accepting a recommendation reads and deletes it (around line 1135). Series progress is written after a series episode plays, using the next season and episode numbers (around line 806). `worker/PROCESS_GROUP_CUTOVER.md` notes that Lounge selections also live in this file.
- **Apollo source before this work:** missing. Movie playback sessions persist in `hmo_media_sessions` (`apps/hearmeout/src/room-media-core.ts`). Nothing in Apollo stored pending recommendations or series progress. `apps/hearmeout/src/xtream-provider.ts` accepts a `getProgress` callback, but no implementation is wired in.
- **Difference:** a restart drops pending recommendations and series resume points.
- **Store (landed on `main` via #292, Oracle `40594995273` success on `7b126d0`):** `apps/hearmeout/src/watch-state.ts` (`HearMeOutWatchStateStore`) uses STRICT SQLite tables `hmo_watch_recommendations` and `hmo_watch_series_progress`, scoped by tenant and user, with take-on-accept. It rejects playback URL, credential and malformed fields. Restart coverage: `tests/hearmeout-watch-state-restart.test.mjs`.
- **Request-flow helpers (landed on `main` via #295, merge `788b767`, Oracle `40605339364` and `40605373397` success on `main`):** `apps/hearmeout/src/watch-request-flow.ts` exports `seriesProgressLookup`, `requestWatch`, `recordRecommendation`, `acceptRecommendation` and `recordSeriesEpisodeQueued`, with provider access injected through `WatchRequestDeps`. Tests: `tests/hearmeout-watch-request-flow.test.mjs`. Nothing imports these helpers yet.
- **Remaining blockers for P08 parity:**
  1. Series playback has no route. `apps/hearmeout/src/xtream-hls.ts` and `xtream-hls-route.ts` serve only VOD ids (`xtream-vod-*`). `movie-provider.ts` filters search results to `xtream-vod-*`, so a resolved `xtream-episode-*` entry cannot be played.
  2. Credential boundary. `xtream-provider.ts` reads Xtream credentials from `process.env` in the web process (loaded through `activity-web.ts`). `movie-provider.ts` and `execution-worker.ts` talk to the donor HTTP routes instead. The consumer must run where the Xtream lookups run, or add an authenticated internal route. This is a design choice, not yet made.
  3. Store path is not configured. No `HEARMEOUT_WATCH_STATE_PATH` or equivalent exists yet.
  4. The Internet Archive fallback that calls `recordRecommendation` is not ported.
- **Next:** resolve blockers 1–3 with a decision, then wire `requestWatch` into the web request path, `recordSeriesEpisodeQueued` after queueing, and `acceptRecommendation` into the accept route. Each step needs a test on the real path before this row can close.
