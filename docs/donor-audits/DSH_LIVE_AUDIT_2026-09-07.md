## Exclusions and evidence still needed

- The old report called a welcome/onboarding card mandatory. This pass located `headless/community-card/[serverId]/page.tsx` but no production reference to that rendering route. Treat the separate card as **unconfirmed usage**, not an automatic port requirement. Canonical onboarding already has an owner.
- `shoutout-card-service.ts` explicitly constructs a placeholder MP4 path from its GIF path. That path is not a real media capability. The separately deployed clip worker is real and is included in DSH-06.
- Diagnostic/test/setup routes, donor credential storage, identity backfill and obsolete bootstrapping are not independent end-user features to copy. Retain necessary migration behavior in controlled migration tooling, not public app actions.
- Source reachability does not prove a raid train or any other feature currently has users/data. Before migration, reconcile actual settings, tracked messages, applications/receipts, schedules, memberships and media against the live volume. Do not silently omit data merely because a UI is empty.
- Provider permissions, phone rendering, actual tier media appearance, egress configuration and restart/rollback acceptance remain live checks. This audit does not authorize retiring either Fly app.
