- Hosted task safety: exact `https://chatgpt.com/c/<conversation-id>` targets only; visible signed-in ChatGPT UI only; existing composer drafts are preserved; Send must become visibly enabled after filling an empty composer; one click maximum; uncertain sends block later tasks and are never retried automatically.
- Tasks use unique completion markers and configurable 1–100 cycle limits. Incomplete work receives a continuation; completion markers end the task; cycle limits and owner-review requests pause for review. Pause during an in-flight cycle preserves the continuation prompt, so Resume does not resend the original prompt. Pause/Stop cannot hide an uncertain send; explicit manual completion is the resolution path.
- Queue state, activity history, and Playwright storage state (cookies, local storage, IndexedDB) use the existing shared Turso database. Node 1 requires the shared Turso URL and token at startup. The temporary Chromium working directory is disposable; no Hostless persistent volume is required.
- Hostless owns scheduling through the embedded `apollo-bulletin-resumer` cron job, configured for a one-minute wake-up. The Node 1 in-process poller is disabled. The cron endpoint is an authenticated, fast wake-up; the Node 1 service serializes work and processes at most one due task per tick. Run now/Resume invoke the same tick immediately.
- The Apollo session gate requires a valid `spmt_token` session through `/v1/auth/session/check` for ordinary `/bulletin/*` requests. Only the cron tick bypasses interactive session auth, and it requires the cron bearer token (or the existing browser-control password). The remote browser console retains its Basic-auth gate.
