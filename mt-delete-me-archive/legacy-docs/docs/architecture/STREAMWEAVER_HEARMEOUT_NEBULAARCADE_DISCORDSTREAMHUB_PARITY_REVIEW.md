## Executive decision

1. Keep ApolloStation as the shared shell and runtime destination; do not recreate or redeploy these products as independent Apollo apps.
2. Preserve the current product owners and app-specific data. Share only the responsibilities already owned by SPMT, Chat Gateway, Stellar Core, HearMeOut/Companion, Overlay Bay, and the canonical XP/inventory services.
3. Reconcile the existing StreamWeaver, HearMeOut, and DSH audits against the pinned commits before reopening old “missing” rows. Several have been implemented since their original review dates; some older handoff lines are themselves stale.
4. Treat ChatTag as the confirmed Nebula Arcade donor because the owner identified `Mtman1987/chat-tag`. It is donor provenance, **not** a new Apollo app ID, service ID, route prefix, worker, or authority. Nebula's canonical Apollo ownership remains `nebula-arcade`.
5. Do not mark a capability verified from a module, test file, green build, inventory comparison, or merged commit alone. Require the capability's real entry point, owner/state, consumer, failure/replay behavior, relevant isolation/security checks, and whatever provider/browser/restore acceptance the workflow requires.

## Ordered continuation and exit gates

1. **Evidence baseline — complete for this audit snapshot:** the confirmed donor mapping and four manual/nightly pairings are merged; the post-merge main run at Apollo `e96b88207607ab5f586592baebbe03b2bc101ca1` completed read-only inventories and REA for all four donor/app pairs, with artifacts checked for expected contents and commit provenance. Rerun after source changes or artifact expiry. Inventory, path/hash comparison and REA output are triage only, not feature parity evidence.
2. **Current gap reconciliation:** refresh the StreamWeaver/HMO/DSH legacy ledgers against the pinned Apollo source and current tests. Correct stale “missing,” “open,” or “pending” statements when later merged commits supersede them; do not overwrite historical results without dates/SHA context.
3. **Nebula/ChatTag:** map Tag aliases/events and each donor Bingo contract; determine donor game list and durable state path; verify current Apollo consumers, XP/event ownership and restart/restore. Keep ChatTag as donor only.
4. **Bounded behavior slices:** prioritize concrete and cross-cutting blockers rather than copying repositories. For each slice record donor entry/source, Apollo owner/path, disposition (keep/adapt/combine/exclude/blocked), test and fresh result, provider/browser evidence, and any tenant/data migration evidence.
5. **Completion bar:** mark `verified` only after a reachable user/provider entry point exercises the real Apollo consumer and durable owner; meaningful success and denial/error/replay behavior are covered; all required scope/tenant/security boundaries pass; and any designated browser/provider/worker/restore acceptance is recorded on the exact tested commit.
6. **Release/cutover:** owner-approved migration inventory, backup, isolated restore, data reconciliation, rollback plan and production acceptance are separate gates. A merged PR, green build or evidence artifact does not itself authorize deployment, changing credentials, routing, or retiring a donor.
